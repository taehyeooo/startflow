# 처음 세팅 (startflow)

## 순서
1. 레포 폴더인지 확인(아니면 `git init` 여부를 묻는다).
2. 서비스에 따라 달라지는 것만 묻는다(한 번에 하나씩, 선택지로):
   - 한 줄 소개(누가, 무엇을 하면, 무엇을 얻는지)
   - 기술 스택(서버·DB·배포·외부 API — 각 외부 서비스의 무료 티어 여부를 함께 확인해 적는다)
   - **가장 먼저 검증할 핵심 가정**(예: "영상 → 장소 추출이 쓸만한 정확도인지")
   - 화면이 있는지(앱/웹) → uiflow 설정 여부
   - 빌드·테스트 명령, 필요한 환경 변수 이름
3. 답을 JSON으로 저장하고 `bash "${CLAUDE_PLUGIN_ROOT}/scripts/init.sh" <답변.json> --dry-run`으로 무엇이 생기는지 보여 준다.
4. 승인 후 `init.sh <답변.json>` 실행. 이미 있는 파일은 덮어쓰지 않고 `*.startflow.*`로 옆에 만든다 — 다르면 사용자와 합친다.
5. 결과: 만든 파일 목록, 다음 할 일(핵심 가정 검증 스크립트부터, 서버가 생기면 devflow `deploy` 설정 채우기).
   첫 커밋은 사용자 확인 후 `chore: 프로젝트 초기 세팅`.

## 고정된 내 기본값 (묻지 않음)
비용 0원 원칙, 개발 순서(검증 → API → 배포), 외부 API는 비동기, 외부 연동은 별도 서비스, 작업 방식(한국어·범위 확정·방법 비교·검증·기록·성능 근거·환경 표시·시크릿·시간 기록), Git 규칙(브랜치 `타입/#이슈-내용`, 커밋 `타입: 내용`만, AI 서명 금지, `Closes #번호`).
