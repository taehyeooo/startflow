## 작업 방식 (모든 작업에 적용)

- **답변은 처음부터 한국어로**: 중간 안내·질문·후보 목록·긴 작업 뒤 최종 요약까지. 영어로 쓴 뒤 번역하지 않는다. 코드 식별자·명령어·파일 경로만 원문.
- **판단이 필요한 작업**: 바로 코드 짜지 말고 ① 문제 범위를 사용자와 확정(모호하면 선택지로 묻기) ② 방법이 둘 이상이면 "해결되는 상황 / 남는 문제 / 부작용"을 비교해 사용자가 고르게 ③ 커지면 단계로 나눠 단계마다 검토 ④ "한 번 돌아갔다"로 끝내지 말고 처음 정한 문제 상황을 검증하는 테스트·확인 절차, 확인 못 한 범위 명시 ⑤ 끝나면 `docs/experience-notes.md`에 문제·조건 / 선택한 방법과 이유(비교한 대안 포함) / 확인한 것·못 한 것. 이유는 추측하지 말고 사용자가 한 말을 근거로.
- **성능·비용 근거**: 고치기 전(before)을 먼저 실측, 추정은 "추정"이라고 쓴다. 결과는 터미널이 아니라 파일로 커밋(benchflow `docs/bench/`). 외부 API 호출(지연·크기·성공/실패)은 첫날부터 로그 테이블에. 조정한 값의 이유와 숫자를 커밋·주석에(감으로 정했으면 그렇다고). 관측(모니터링)은 트래픽이 없을 때부터.
- **실행 환경 표시**: 측정·테스트·QA 결과에는 로컬/운영을 항상 적고, 가능하면 둘 다.
- **시크릿**: DB 비밀번호·JWT·API 키 같은 실제 값은 외부(문서·업로드·외부 API)로 보내지 않는다. 채팅에는 요청할 때만. worktree를 지우기 전에 무시된 파일(.env 등)이 그 안에만 있는지 먼저 확인한다.
- **배포·QA 시간 기록**: 배포는 devflow `deploy`, QA는 qaflow(`start`~`stop`)로 해서 걸린 시간을 남긴다.

## Git 컨벤션 (예외 없이 항상 적용)

- 브랜치명: `타입/#이슈번호-내용` (예: `feat/#12-map-api`)
- 커밋 메시지: `타입: 작업 내용` 형식만 사용. 타입은 feat/fix/docs/style/refactor/chore/perf/test 중 하나.
  - `git commit -m "타입: 내용"` 형식으로만 작성 — 그 외 어떤 텍스트도 붙이지 않는다.
  - **커밋에 AI 관련 서명/트레일러를 절대 추가하지 않는다**: "Generated with Claude Code", "Co-Authored-By: Claude" 등의 문구나 🤖 이모지 금지. 커밋 작성자는 오직 사용자로만 표시되어야 한다.
- PR 본문에 `Closes #이슈번호` 포함

## 자동화 플러그인

- devflow: `ship`(이슈→PR→머지), `deploy`, `local-server`, `ops-check`, `work-record`, 커밋 검사 훅
- qaflow: 테스트 데이터 자동 정리, 시나리오 재생, API 스모크, QA 환경, 보고서
- uiflow: 수정 후 검사 훅, 글자 크기별 화면 훑기, 전·후 비교 (화면이 있는 프로젝트)
- benchflow: 측정 N회 통계를 `docs/bench/`에 커밋, 전·후 비교
- 서비스별 값(서버·DB·API·좌표)은 `~/.config/<플러그인>/<레포 이름>.json` — 레포 밖, 공개 레포에 올리지 않는다
